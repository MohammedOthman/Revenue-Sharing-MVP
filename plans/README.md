## Why these five

These are the highest-leverage vetted findings from the audit: a low-privilege
user can currently process payouts and delete financial records (001), overwrite
a payout amount to bypass the server-side share computation (002), inject
executable formulas into an exported statement (003), bomb password-reset emails
and keep access after a reset (004), and the app ships known-vulnerable
dependencies with no gate (005). Every one is high-confidence, small-to-medium
effort, and has a clean verification story.

## Findings considered and rejected

- **SQL injection via `getRevenueByPeriod` `TO_CHAR` format** (`revenue.model.js`):
  the format string comes from a fixed internal whitelist (`YYYY-MM`/`YYYY-Q`/`YYYY`),
  never from request data — not injectable. Rejected (documented as a style
  inconsistency only; see plan 002 maintenance notes).
- **SQL injection via reset-token interval** (`passwordReset.model.js`): uses a
  parameterized `($4 || ' minutes')::interval` with an internal constant. Safe. Rejected.
- **Cross-tenant mass data export** (reported as IDOR across customers): the
  platform is single-tenant-per-client by design (see `PRELAUNCH_CHECKLIST.md`
  P0.1), so there is no cross-tenant surface. The real issue — a low-privilege
  user reading all data *within* the tenant — is folded into plan 001. Rejected as
  a separate finding.
- **`trust proxy: 1` spoofing** (`app.js:28`): correct for the documented
  single-reverse-proxy deployment (Render/Railway/Docker/Replit). Deployment-
  dependent, LOW confidence; noted in plan 001 maintenance notes, not planned.

## Deferred (real, lower leverage — not yet planned)

Recorded so they aren't re-audited; promote to plans on request:

- **Perf:** unbounded list queries + full in-memory CSV; missing indexes for
  `type`/`document_type`/period filters; frontend refetches full dataset after
  every mutation. (Pagination is a documented P1 — these compound it.)
- **Tech-debt:** update-whitelist + filter-builder copy-pasted across 6 models;
  ~40 duplicated controller try/catch blocks with a dead central error handler;
  schema bootstrap replays full DDL on every boot (no migration framework);
  `audit_logs` grows with no retention.
- **Tests/DX:** browser E2E not wired into CI; order-dependent API suite (shared
  mutable `state`); no lint/format gate; untested branches (DELETEs, admin user
  mgmt, CORS prod branch, mailer Resend path).
- **Correctness:** currency handled as JS floats against DECIMAL columns
  (sub-cent drift accumulates in SUMs) — medium confidence, medium effort.
- **Security (lower):** JWT in localStorage with 7-day life and no revocation
  (already a documented P1); DB TLS `rejectUnauthorized:false`; role value not
  constrained to an enum on register/update.
- **Docs:** `PRELAUNCH_CHECKLIST.md` says "16-test suite" in one place, "20" in
  others; `.env.example` omits `APP_PORT` and `FRONTEND_DIST`.
